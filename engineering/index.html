[Projects]

  1. ABB Offline Coder

    [Project page]

    One-sentence request in, validated ABB RAPID spray-painting program out, with no network.

    Problem
    Engineers programming ABB spray-painting robots work on air-gapped industrial PCs and write RAPID by hand from the manuals, which is slow and error-prone.
    What I built
    A command-line tool with a layered pipeline: query rewriting, hybrid retrieval (BGE vectors + BM25) over 7,497 chunks from 10 official ABB manuals, a quantized Qwen2.5-Coder-7B served locally by Ollama, and RAPID post-processing with 8 rule checks.
    Results
    • Runs fully offline; about 25 s per program on CPU, 8–15 s with the 3B model
    • Generated modules import into RobotStudio; 67 unit tests cover the core logic at 90–100%
    • Windows / macOS / Linux, with a one-step offline installer for USB deployment
    Stack

  2. Newton VLA Demo

    [Project page]

    A live embodied-AI demo on a MacBook: no GPU, no cloud.

    Problem
    A language model takes 2–10 s to answer, far beyond the 60 fps frame budget of a live robot-arm demo.
    What I built
    A dual-arm simulation on Newton XPBD physics with a pygame UI. A hybrid VLA pipeline lets a 1 ms keyword preflight start the arm at once while the language model refines the plan in the background; ball catching uses closed-form MPC, and blocks are real rigid bodies that stack and topple.
    Results
    • 56.2 fps on average, CPU-only
    • 250 tests passing; 62–82% measured ball-catch rate
    • Documented in a 22-page design report and a 29-page defense deck
    Stack
    PythonNewton (XPBD)pygameMPCLLM CLICI

  3. TianWen

    [Project page] [Code]

    One open-source framework for training detectors together with vision-language models.

    Problem
    Detectors are fast but semantically shallow; VLMs understand more but are slow. Each fusion idea usually needs its own codebase.
    What I built
    An Apache-2.0 framework that pairs any registered detector (YOLOv8/v11, RT-DETR, RF-DETR, Grounding-DINO) with any VLM (Qwen2-VL, InternVL3) through distillation, feature fusion or decision fusion, configured with Hydra and trained on PyTorch Lightning.
    Results
    • Three fusion strategies switchable from the command line
    • New models or fusion modes plug in through a decorator-based registry
    • Multi-GPU training; benchmark results are in progress
    Stack
    PythonPyTorchPyTorch LightningHydraUltralyticsQwen2-VLInternVL3
